# תרחישי שימוש (User Flows)

## צד העובד

### 1. התחברות
1. עובד מזין מספר עובד
2. המערכת מזהה ומציגה את שמו
3. כניסה למסך הראשי של העובד

### 2. הגשת זמינות
1. עובד רואה לוח שנה של הרבעון הנוכחי
2. על כל תאריך הוא יכול לסמן:
   - **לא יכול לעבוד** (אדום) — המערכת לא תציע את העובד ליום זה
   - **מעדיף לעבוד** (ירוק) — אינדיקציה חיובית למנהל
   - **מעדיף לא לעבוד** (כתום) — אינדיקציה שלילית למנהל, אבל לא חסימה
   - **ללא העדפה** (ברירת מחדל) — רגיל
3. העובד שומר ויכול לערוך עד למועד שנקבע

## צד המנהל

### 1. התחברות
1. מנהל מזין מספר עובד + סיסמה
2. כניסה למסך הניהול הראשי

### 2. הגדרות (Settings)

כל ייבוא הנתונים (מלבד ייצוא/ייבוא JSON במסך השיבוץ) מרוכז בדף ההגדרות תחת טאבים נפרדים.

#### טאב: עובדים

**רשימת עובדים:**

הרשימה מציגה לכל עובד: שם, דרגה, סטטוס פטור (אם פטור — מוצג עם הסיבה), תצוגה מקוצרת של הערות. ניתן לסנן/לחפש לפי שם.

**עריכה פרטנית:**

לחיצה על עובד פותחת פאנל עריכה:
- **פטור** (`is_exempt`) — toggle. כשמופעל: שדה סיבה חובה (`exemption_reason`) ושדה "האם מקבל הקצאה" (`receives_shift_allocation`). עובד פטור עדיין מוצג ברשימת השיבוץ עם אזהרה אדומה וניתן לשבץ כפוי.
- **אילוצים קבועים** (`standing_constraints`) — textarea: אילוצים שחוזרים כל רבעון, כגון "ימי לימודים ראשון שלישי שישי". מוצגים בנפרד מהערות.
- **הערות** (`notes`) — textarea: אילוצי רבעון נוכחי, מידע רלוונטי שצריך לדעת בעת שיבוץ. מקביל לעמודת הערות בקובץ העובדים. מיובא מטפסי הגשת אילוצים.

**ייבוא עובדים מקובץ XLSX:**

מיפוי עמודות מקובץ העובדים:

| עמודה בקובץ | שדה ב-DB |
|---|---|
| מספר אישי / worker_id | `worker_id` |
| שם | `name` |
| דרגה / ענף | `rank_id` |
| הערות | `notes` |
| פטור | `is_exempt` |
| סיבת פטור | `exemption_reason` |
| תאריך תום שירות (תת"ש) | `release_date` |

1. מנהל מצרף קובץ XLSX
2. המערכת מנתחת ומציגה תצוגה מקדימה עם מיפוי עמודות
3. **זיהוי עובדים משוחררים**: עובדים שה-`release_date` שלהם חל ברבעון הקודם או לפניו מסומנים אוטומטית בתצוגה המקדימה — עם אפשרות מחיקה לפני האישור
4. מנהל מאשר → עובדים נשמרים/מתעדכנים ב-DB (upsert לפי `worker_id`)

**ייבוא תגובות טופס אילוצים:**

פורמט הטופס: `Timestamp, שם פרטי + משפחה, ענף, אילוצים`

1. מנהל מצרף קובץ CSV/XLSX של תגובות טופס
2. המערכת מנתחת ומציגה טבלה — כל שורה כוללת: שם, ענף, תוכן האילוצים, שדה חיפוש/בחירת `worker_id`
   - שורות כפולות (אותו שם הגיש פעמיים) מוצגות כשורות נפרדות — המנהל מחליט לכל אחת בנפרד
   - עמודת "ענף" מוצגת לעזר בזיהוי הנכון
3. לכל שורה: המנהל בוחר `worker_id` מרשימת העובדים (חיפוש לפי שם)
4. לכל שורה: המנהל בוחר **הוסף לסוף** / **החלף** ביחס ל-`notes` קיימות
5. מנהל לוחץ "ייבא שורות מסומנות" — ה-`notes` של העובדים המסומנים מתעדכנות

#### טאב: תאריכי משמרות

**יצירת רבעון:**
1. מנהל מזין מזהה רבעון (פורמט `2026-Q3`), תאריך התחלה וסיום
2. לוחץ "צור" → הרבעון נשמר ב-DB

**העלאת תאריכי משמרות (תחילת רבעון):**
1. מנהל בוחר רבעון קיים
2. מצרף קובץ (XLSX / CSV)
3. המערכת מנתחת את הקובץ ומציגה תצוגה מקדימה:
   - רשימת תאריכים
   - סוג משמרת לכל תאריך (כל גיליון XLSX = סוג משמרת)
   - סימון סופ"ש (חמישי-שבת) אוטומטי
4. מנהל מאשר → הנתונים נשמרים ב-DB

#### טאב: דרגות / סוגי משמרות / כשירות

ניהול דרגות, סוגי משמרות ומטריצת כשירות — כמתואר בסעיף 7 להלן.

### 4. שיבוץ עובד למשמרת (Drag & Drop)

1. מנהל לוחץ על תאריך משמרת ברשימה (או בוחר אותו)
2. רשימת העובדים בצד ימין מתעדכנת ומציגה.
   כרטיסיית עובד מציגה גם `notes` ו-`standing_constraints` אם קיימים — כדי שהמנהל יראה הקשר רלוונטי מבלי לעבור להגדרות.
   - **כשירים וזמינים** — מוצגים ראשונים, ממוינים לפי ימים מאז משמרת אחרונה (הכי הרבה זמן = ראשון)
   - **כשירים אבל מעדיפים לא** — מוצגים עם אינדיקציה כתומה
   - **לא כשירים** — מוצגים עם אינדיקציה אדומה
   - **לא זמינים (הגישו שלא יכולים)** — מוצגים עם חסימה
   - **פטורים** — מוצגים עם סימון פטור
   - **כבר שובצו הרבעון** — מוצגים עם סימון ✓
3. מנהל גורר עובד לתאריך משמרת

#### אינדיקציות בעת שיבוץ

| מצב | אינדיקציה |
|---|---|
| עובד כשיר וזמין | ירוק — שיבוץ רגיל |
| עובד מעדיף לא לעבוד ביום זה | כתום — אזהרה קלה |
| עובד לא כשיר לסוג משמרת זה | **אדום גדול** — אזהרה חמורה, שיבוץ עדיין אפשרי |
| עובד הגיש שלא יכול ביום זה | **אדום גדול** — אזהרה חמורה, שיבוץ עדיין אפשרי |
| עובד כבר עשה סופ"ש השנה | **אדום גדול** — חריגה מכלל שנתי |
| עובד כבר שובץ הרבעון | אזהרה — אבל אפשרי (החלפות, חריגים) |
| עובד פטור | **אדום גדול** — שיבוץ עדיין אפשרי |

> **עיקרון מנחה**: המערכת לעולם לא חוסמת שיבוץ. היא רק מציגה אזהרות ברמות שונות. למנהל יש את המילה האחרונה.

### 5. שיבוץ כפוי

כשהמנהל משבץ עובד למרות אזהרה אדומה:
1. מודאל קופץ: "שיבוץ זה חורג מהכללים. סיבה?"
2. מנהל מזין סיבה בטקסט חופשי
3. השיבוץ נשמר עם `is_forced = true` והסיבה

### 6. שמירת התקדמות

1. מנהל לוחץ "ייצוא התקדמות"
2. המערכת מייצאת קובץ JSON עם כל מצב הרבעון:
   - תאריכי משמרות
   - שיבוצים שבוצעו
   - זמינות עובדים
3. לחצן "ייבוא התקדמות" — מנהל מעלה JSON וממשיך מאותה נקודה

### 7. ניהול דרגות, סוגי משמרות וכשירות

מדף ההגדרות, טאבים ייעודיים:

1. **דרגות** — הוספה, עריכה ומחיקה של דרגות
   - מחיקה אפשרית רק אם אין עובדים משויכים לדרגה
2. **סוגי משמרות** — הוספה, עריכה ומחיקה של סוגי משמרות
   - מחיקה אפשרית רק אם אין תאריכי משמרות משויכים לסוג
3. **כשירות** — מטריצה אינטראקטיבית:
   - שורות = דרגות, עמודות = סוגי משמרות
   - לחיצה על תא מחליפה בין כשיר/לא כשיר
   - לתאים כשירים ניתן להגדיר מספר עדיפות
   - שינויים נשמרים מיידית

### 8. סקירת סיכום

לפני פרסום סופי, מסך סיכום מציג:
- כל השיבוצים
- עובדים שטרם שובצו
- שיבוצים כפויים (מסומנים)
- חריגות מכללים
